HTTP ENDPOINTS

Small, inspectable API surface.

These endpoints return the app's current local catalogue. They are not a live connector to external stores.

GET
/api/health

Service mode, stores/listings counts, low-stock count and most recent inventory timestamp.

GET
/api/search?q=charger

Search products by name, category, keyword or store name. Optional parameters include category, price, availability, sort and coordinates.

GET
/api/stores

Store metadata with approximate map coordinates and opening-hour fields.

GET
/api/item/1

One inventory listing with confidence and freshness metadata.

POST
/api/plan

Accepts JSON such as {"products":["USB-C 20W Charger","A5 Notebook"]} and returns a greedy multi-store coverage plan.

↗

What production “real time” would need

Authenticated retailer connectors or scheduled POS inventory feeds, webhook/API validation, per-store data ownership, error monitoring, rate limits and a secure deployment. NearCart already surfaces the update time so stale stock can be distinguished from recently synchronised data.
